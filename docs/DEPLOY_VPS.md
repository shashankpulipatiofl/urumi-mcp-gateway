# Local → production-like VPS (k3s)

The production install uses **the same charts**. Only `values-prod.yaml` and some Secrets differ.

## 1. Server
Any Ubuntu 22.04/24.04 VPS with 2 vCPU / 4 GB RAM (Hetzner, DigitalOcean, Oracle free tier…).
DNS: point `store.example.com` and `app.example.com` (A records) at the VPS IP. Open ports 80 and 443.

```bash
curl -sfL https://get.k3s.io | sh -          # k3s = Kubernetes + Traefik ingress + local-path storage + NetworkPolicy controller
sudo cat /etc/rancher/k3s/k3s.yaml            # copy to your laptop as ~/.kube/config (replace 127.0.0.1 with the VPS IP)
```

## 2. TLS with cert-manager (optional, recommended)
```bash
helm repo add jetstack https://charts.jetstack.io && helm repo update
helm install cert-manager jetstack/cert-manager -n cert-manager --create-namespace --set crds.enabled=true
kubectl apply -f - <<'EOF'
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata: { name: letsencrypt-prod }
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: you@example.com
    privateKeySecretRef: { name: letsencrypt-prod }
    solvers: [{ http01: { ingress: { ingressClassName: traefik } } }]
EOF
```

## 3. Images
Push a tag (`git tag v1.0.0 && git push --tags`). CI builds multi-arch images to
`ghcr.io/<you>/urumi-{store,woocommerce-mcp,demo-upstreams,gateway,dashboard}:1.0.0`.
Make the packages public, or add an `imagePullSecret`. Replace `YOUR_GITHUB_USER` in `values-prod.yaml`.

## 4. Secrets (created once, outside Helm and git)
```bash
kubectl create namespace urumi
kubectl -n urumi create secret generic urumi-platform-secrets \
  --from-literal=secret-key="$(openssl rand -hex 32)" \
  --from-literal=encryption-key="$(openssl rand -hex 32)" \
  --from-literal=admin-password='CHOOSE-A-STRONG-ONE' \
  --from-literal=postgres-password="$(openssl rand -hex 16)" \
  --from-literal=fx-api-key="$(openssl rand -hex 20)"
kubectl -n urumi create secret generic urumi-store-secrets \
  --from-literal=mariadb-root-password="$(openssl rand -hex 16)" \
  --from-literal=mariadb-password="$(openssl rand -hex 16)" \
  --from-literal=wp-admin-password='CHOOSE-A-STRONG-ONE' \
  --from-literal=wc-consumer-key="ck_$(openssl rand -hex 20)" \
  --from-literal=wc-consumer-secret="cs_$(openssl rand -hex 20)" \
  --from-literal=mcp-token="$(openssl rand -hex 24)"
kubectl -n urumi create secret generic urumi-llm --from-literal=api-key=YOUR_GEMINI_OR_GROQ_KEY
# for Groq add  -f deploy/helm/urumi-platform/values-groq.yaml  to the helm command below
```
(For GitOps, use Sealed Secrets or External Secrets instead of typing these.)

## 5. Install
```bash
helm dependency update deploy/helm/urumi-platform
helm upgrade --install urumi deploy/helm/urumi-platform -n urumi -f deploy/helm/urumi-platform/values-prod.yaml --wait --timeout 15m
kubectl -n urumi get pods,ingress,certificate
```

## What changed between local and prod (all through Helm values)

| | local | prod |
|---|---|---|
| domain | `*.localhost` | `store.example.com`, `app.example.com` |
| ingress / TLS | Traefik, http | Traefik, https via cert-manager annotation + `tls:` blocks |
| storage | default class, small | `local-path`, 10Gi store volumes, 5Gi Postgres |
| secrets | generated by Helm | `existingSecret` (created above) |
| images | local `:dev` imported into k3d | GHCR, pinned versions |
| replicas | 1 | gateway 2, dashboard 2 |
| cookies | plain | `Secure` (derived from https) |

On a cluster whose ingress controller isn't Traefik (e.g. ingress-nginx), also set
`ingress.className`, `woocommerce.ingress.className` and
`networkPolicy.ingressController.{namespace,podLabels}` (and the same under `woocommerce.networkPolicy`).
